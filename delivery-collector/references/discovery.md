# 只读发现与证据匹配

## 共用方法

1. 根据调用确定工作空间、项目根、对象、批次。“精准匹配”按真实工作空间标识/名称核实，不用相近日期或最近会话替代。无人值守时范围缺失/无法区分批次记异常，不停等确认。定时收集在发现前固定cutoff_at，用消息/状态/版本证据重建截止快照。
2. 读取实际问题文件和源素材 manifest；排除 rubric、答案、历史交付。`roster` 的邻近文件只是候选素材，必须人工/agent 分类。
3. 读取当前应用数据库 schema、会话元数据、提交消息、上传素材记录与末次正式交付。工具可用于查询，`sqlite` 为只读分页助手，不内置固定 schema。对需要的全部页进行读取，不能看前100行后认定未执行。
4. 建立“题号 → 根会话/独立提交 → 项目目录 → 正式文件”的映射。用真实正文和素材身份匹配，标题、日期后缀只辅助。匹配证据不足标待确认。
5. 提取正式交付工具结果及正式助手答复中的路径，避免只看下载组件导致漏收。**没有present_files/result_file等组件，正式输出给出的最终文件路径对应文件真实存在且完整可读，也是成功交付。**记录正式声明、原路径、实际路径、会话ID、消息ID、时间、哈希；相对路径按会话工作目录解析，沙箱路径/URL核实映射，不按同名搜索任取。仅“将生成/计划保存”的输入或不存在路径不算交付。
6. 记录原始状态、截止状态证据、正式文件核查是否完整、耗时及来源。仍运行无组件时，先检查正式路径和项目最终文件，再判断无交付/超时。截止仍无完整成果才归一为超时；已结束但有真实最终文件路径不能误判失败。排除thinking/reasoning，正式可见性不明记异常。

所有下面路径都是历史应用布局线索，不是强制位置或稳定 API。优先用本次配置/应用实际数据目录；不同平台、版本、账号、UAT/正式环境可能不同。只读打开 SQLite；不要写 DB、删除 WAL、复制单个运行中主 DB 后忽略 WAL，或输出认证配置、token、密钥。遇数据库锁先使用数据库安全快照接口或应用 UI，不修改应用。

## WorkBuddy

常见本地线索：用户目录 `.workbuddy/workbuddy.db`、`.workbuddy/projects/` 下的会话 JSONL；项目根可能与应用数据目录不同。先列数据库 schema 确认会话表（如 `sessions`）及工作目录、创建时间、父会话等字段。`custom_title` 不能证明题号。按 ID 寻找同会话原始消息与工具事件，读取用户提交题目/附件，核实是否根任务。

历史正式交付工具常见 `present_files`，但不是成功必要条件。核查成功结果与完整正式答复中的实际路径；无组件但正式路径文件完整可取得时成功。失败调用输入不算交付。排除中间产生但未正式提供的build_report.py等。完成任务耗时按UI含义核实；超时只用真实提交/执行开始至截止的时间差并标“经过时长”，不取项目创建/更新时间差。

## MobileWork

常见本地线索：用户目录 `.mobilework/xdg/data/opencode/opencode.db`，项目根可能为 `MobileWork/<项目ID>`。先查看 `session`、`message`、`part` 等实际表结构，核实目录、父会话、ID 和数据字段。不要仅根据 `title` 匹配。

读取用户消息与上传部分，解析part结构化JSON。历史正式交付工具常见 `result_file`，但不是必要条件；无工具/组件时检查正式答复给出的路径，文件完整可取得即可成功。input计划路径不算交付。失败/运行中工具的临时文件、缓存、思考part不当正式文件；不能把根会话running与单个工具running混淆。同题根会话按本批次提交证据排序。

## 无直接数据库访问

可用应用导出记录、接口、连接器或 UI 读取同样的证据。skill 不要求两个应用同时可访问。不支持的对象也能使用共用规则，但先验证其记录读取方式；不能声称已自动适配全部产品。agent 具备原生 UI 工具时按该工具要求操作，不通过脚本注入或模拟隐藏控件绕过权限。
