# 决策与归档规则

## 运行身份与状态

一次收集只针对调用指定的一个对象。按输入题目、上传素材、对象、工作空间、批次、会话 ID 和提交证据匹配；名称/顺序/文件名不能独立证明归属。保留题号为标识文本（例如 1.1、W1），防止 Excel 数值误差形成 1.1000000000000001。

两次独立提交须为同题、同素材。仅规范换行、行尾空白等传输差异，不删除数字、日期、否定词或改写正文来凑匹配。上传名一致但内容不可验证时记录证据限制；遇重复题目依素材和批次消歧，不能靠模糊分数强行分配。

按实际提交时间区分第一次和第二次，不按完成时间。子代理不算独立运行。同一会话暂停后继续、未改题目或素材时仍是同次；实际多个独立任务不能仅因共用会话就合并。

状态：`success` 实际成功；`failed` 明确失败/不完整，或截止规则认定超时；`running` 执行中原始状态；`unknown` 证据不明。成功须已取得全部必需、可读取的正式交付，未因最终错误/输出上限缺失成果。**正式输出给出最终文件路径，且文件真实存在可取得，等同于组件提供交付；缺少下载组件不构成失败原因。**中途已恢复错误不单独否定成功。仅“完成”状态、存在扩展名或未验证声明仍不够。核查格式、图表/工作表与必需文件齐全，不判断结论正确性或rubric得分。

## 选取矩阵

| 第一/第二次 | 选择 | Excel 用时 | Excel 说明 |
|---|---|---|---|
| 第一次成功，第二次任意 | 第一次 | 第一次实际用时 | 一次运行成功 |
| 第一次失败，第二次成功 | 第二次 | 第二次实际用时 | 第一次用时、实际失败原因；第二次运行成功 |
| 两次失败 | 第二次正式界面输出 DOCX | 两次测试均未成功 | 分别记录两次用时与实际失败原因 |
| 第一次成功、第二次超时 | 第一次 | 第一次实际用时 | 一次运行成功，不追加第二次失败影响结论 |
| 第一次超时、第二次成功 | 第二次 | 第二次实际用时 | 第一次截止耗时、超时原因；第二次运行成功 |
| 一次失败另一次超时，或两次超时 | 第二次界面输出/核查DOCX | 两次测试均未成功 | 分别记录两次耗时和原因，超时项注明运行时间过长 |
| 第一次无法确认，第二次成功 | 暂不选择 | 不写确定结论 | 待确认，不能跳过第一次的不确定性 |
| 只发现一次成功 | 该次 | 该次用时 | 一次运行成功；仅发现一次运行 |
| 只发现一次失败 | 待确认 | 暂不登记 | 仅发现一次失败，未发现第二次记录 |
| 大于两次 | 先消除别的批次/子代理/继续 | 未能消歧则不登记 | 列出全部候选与问题 |
| 没有匹配运行，发现范围完整 | 未执行 | 留空 | 留空，发现表注明未执行 |
| 记录不可读/覆盖不足/有未归属线索 | 待确认 | 不更新 | 发现表记证据缺口 |

第二次即使更优，不替代第一次实际成功。第一次失败仍保留完整发现记录，但不把两次文件拼接为完整交付。第一次成功时额外运行正在运行也不阻碍第一次收集。

两次失败的 DOCX：`<前缀>-<题号>-未成功任务界面输出.docx`。忠实保存第二次已经显示的正式回答、正式操作结果和可见错误，排除 thinking/reasoning/内部推理/隐藏工具日志；不按关键词删除正式正文中的“思考”二字。以原消息/part 类型和可见性排除。可包括正式图像与表格，不用摘要替代全文。**默认正式交付仅这个 DOCX，不另收失败的部分文件。**第一失败输出只在审计引用中保留，Excel 记录两次情况。正文无法取得或非文本内容无法保留时待确认，不生成声称完整的替代文件。

## 定时收集截止与超时

定时调用以收集启动时固定的cutoff_at为本批统一截止，而不是发现/复制结束时间。所有会话按该时点的状态、正式输出和文件版本判断；不设任意分钟阈值、不无限等待，也不操作终止原会话。非定时、未指定截止的调用保留running为待确认，不自动套超时。

先检查正式输出中的路径及对应实际文件，再判断是否“无交付”。截至截止仍运行，且已核实没有实际正式交付或必需成果仅部分完成，归一为failed，原因写“运行时间过长，判定为执行失败”，补充无交付/缺项事实。仍运行但完整正式交付已在截止前取得的可判success；存在任意文件不代表完整交付。UI状态不明、记录读取失败、仅未找到下载组件，不能当作超时证据。

完成于截止后，须重建截止时的状态；截止后才出现/替换的文件不混入本批。不用文件mtime猜交付时间；记录正式消息/工具交付时间或已保存的截止快照。来源或版本无法证明时记异常，不默认为截止前成功。先归一各次状态，再按首次成功优先的矩阵选择；首次成功时额外运行的超时只在发现清单记录。

两次均失败且第二次超时：不等待任务结束或最终回答完整，DOCX原样保存截止时已经显示的正式内容，并单列“收集核查记录”说明截止仍运行、是否有实际交付、会话ID和耗时。`output_snapshot_complete`表示截止时已显示内容是否全部读到，与回答是否写完无关。**已核实确无正式输出**时可以仅保存该事实记录，不能把收集者描述伪装成受测对象回答；输出未读全则保存可取得内容和缺口说明，不声称完整或没有输出，列待核查。仍不包括思考过程，也不额外收集部分附件。

执行结论与文件保存分开处理：两次失败已确认，就独立按矩阵登记Excel两次用时及原因。Word提取、生成或复制失败时仍登记该结论，说明追加“输出快照保存失败（见核查清单）”，实际文件状态如实标异常；不是把未保存记为已收集。耗时证据有缺口只将该次时长记为无法确认，不把已确认超时改回未知。任务归属、截止状态或交付核查本身不确定时仍待确认，不借此放宽成功标准。

## 用时

优先取客户端该次回复/完成状态的执行时长，记录证据及单位。继续执行的各段实际执行时间求和，先检查客户端显示是否已经累计，避免重复相加。用户等待、暂停、重试间隔不计。不得用项目创建/更新时间差或文件时间戳估计。无法确认则成功行用时留空，说明追加“用时无法确认”；两次失败仍填“两次测试均未成功”，各次说明写“用时无法确认”。可保留客户端明确的原格式，不通过模糊日期计算时间。

超时运行优先使用有截止时点证据的客户端时长，否则用实际提交/执行开始至cutoff_at的差，明确标为“截至收集时经过时长”；实际开始未知可用真实提交时间，但不能用项目创建时间。可确认暂停须扣除，无法区分等待/暂停时不能声称纯执行用时。时区必须明确，缺开始证据则耗时无法确认，不编造。成功结束任务仍用原客户端口径，不改为收集时间减开始时间。

## 文件收集

以页面正式交付和正式声明为依据，全部实质性交付、互补附件、等价正式导出都保留。页面声明文件已生成、无按钮但能定位最终文件时可复制，注明该声明与目录证据。只有声明没有可取得文件不能成功。

不收源素材、题目、rubric、答案、临时脚本、缓存、工作区日志和旧版本。明确正式交付的代码附件可以收；不能一概排除 .py，也不能一概收集工作区 .py。目录不是全部交付，按经核实的文件清单复制。相同文件名/扩展名不代表同内容；哈希相同的不同正式附件也保留其来源记录。

单文件：`<调用前缀>-<现有唯一题号>-<原文件名.ext>`，保存在该题已有文件夹中，保留扩展名。前缀含版本，按本次输入，不根据模型猜前缀。不把项目名中的日期和 data/deep/normal 再加入。对象前缀与 Excel 对象身份对应。

多文件项目：外层目录加对象和题号前缀，内部名/相对路径原样保留，清单枚举每个依赖。HTML 与相邻资源有相对引用时作为项目打包，不重命名 HTML 破坏链接。外部 CDN/远程数据访问失败如实注明，不擅自修复。缺资源/无法确认显示则待确认或明确不齐全。实际启动涉及未知代码、依赖安装、外部访问时按当前授权检查，不把程序可执行当成安全。

同目标同哈希可跳过；同名不同内容不覆盖，列冲突。原始文件不移动、不删除、不改名。复制前后哈希不一致或来源变动时不登记成功。清单必须区分“发现”和“已复制”。

## Excel 与核查清单

默认查数据集文件夹中的测试结果记录 Excel；按 [excel.md](excel.md) 自动定位调用指定的测试对象槽位并更新其表头，缺失时自动向右扩展。支持1/2/3对象布局，仍一次收一个。无人值守时不能临时停等列选择；多份候选或布局歧义先按题号/题名等证据消歧，不能解决则记异常、继续其它明确项。

本次明确指定的槽位按输入身份填写表头和已确定题结果，先备份，不再因旧对象名称/模型不一致要求确认。不任意占用第一个空槽位。只改本次对象表头、已确定执行题的用时及说明；新增组仅复制格式，不复制旧结果/公式。未执行/待确认题不填失败、不清除旧值；在清单注明旧值不是本批结果。不同对象数据、样式及其它工作簿部件保持原样。

清单分为任务与运行发现、交付文件明细、待确认与人工核查。包含每题要求、候选会话、来源引用、选择依据、文件源/目标/大小/哈希、复制/登记结果、完整性检查及人工核查栏。两次都保留审计（第二次额外运行也保留），仅选中一次进入正式交付。未执行维度也在发现表标明，不强制补跑。另存 JSON，方便重入与审计。保留每次批次的记录，不覆盖前次人工核查。

收集结束可生成自动结果，但人工核查不能由 agent 自称完成。必须在总结中显式列出未解决项。
